- [Back-in-stock alerts](back-in-stock-alerts.md) — closes the loop on the shop's restock requests, with **nothing configured in Notion**: no automation, no webhook, no added property. Two earlier drafts used a Notion inventory automation + a `Restock Notified` checkbox and were cut on the owner's call — this branch is the one retiring Notion-side plumbing. Instead it is a **sweep** (`notifyRestock`) on two triggers the app already owns: a fourth pass in the **nightly reconciliation cron** and the studio dashboard's **`restock-alert` tool** (item optional — blank sweeps everything in stock, which is the cron's mode). Reads inventory **fresh** (bypassing the 60s cache, else a same-day press reports the piece still sold out), matches waiting requests by the exact `Item` name, gates per size (**fails closed**), and claims each request in a new Postgres table `restock_alerts` (`insert … on conflict do nothing`, keyed on the request's Notion page id; a claim error skips the send — a duplicate beats a delay). `POSTGRES_URL` is a **hard** requirement here, unlike every other DB caller: unset ⇒ warn + `attention`, since without the marker a nightly sweep re-emails everyone nightly. Setup is one migration run. Renaming an inventory item orphans older requests; the sweep reconsiders every request ever filed.
