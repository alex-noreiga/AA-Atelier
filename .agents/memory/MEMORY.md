- [Automatic shop inventory decrement](shop-inventory-decrement.md) — a paid shop order now writes one Notion **"order lines"** row per purchased item, which **is** the stock decrement: inventory's `Units Sold (auto)` rollup sums each line's `Counts Toward Sold` formula through the line's `Item` relation, and `Quantity Available` subtracts it. Almost nothing is new — the whole mechanism already existed in the workspace and had never fired, because checkout recorded items only as free-text bullets and the lines table stayed empty. So the old "auto-decrement would need a new writable count property plus reservation logic" note was wrong on both halves; **don't reintroduce a count property.** Written **best-effort, per line** at the tail of `processPaidShopOrder` and logged at `error` (a throw would 500 the webhook into a redelivery that early-returns at the dedupe guard, losing the lines anyway); a line whose Stripe product carries no `variantId` is **skipped**, since without the `Item` relation it decrements nothing. `size` is now stamped on the Stripe product metadata rather than parsed back out of the display name, and `Unit Price` stays the **listed** price so `Items Subtotal` vs `Total` still shows discounts. `setShopOrderCancelled` ticks **`Voided`** alongside `Cancelled` — that's what puts a cancelled order's units back — while **returns deliberately don't void** (a returned piece may be unsellable). Still **no reservation**: stock moves at payment, so simultaneous checkouts can oversell the last piece. - [Back-in-stock alerts](back-in-stock-alerts.md) — closes the loop on the shop's restock requests, with **nothing configured in Notion**: no automation, no webhook, no added property. Two earlier drafts used a Notion inventory automation + a `Restock Notified` checkbox and were cut on the owner's call — this branch is the one retiring Notion-side plumbing. Instead it is a **sweep** (`notifyRestock`) on two triggers the app already owns: a fourth pass in the **nightly reconciliation cron** and the studio dashboard's **`restock-alert` tool** (item optional — blank sweeps everything in stock, which is the cron's mode). Setup is one migration run. Renaming an inventory item orphans older requests; the sweep reconsiders every request ever filed.
